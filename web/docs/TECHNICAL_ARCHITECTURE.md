# Technical Architecture

## Stack
TypeScript (strict) · Three.js 0.187 (WebGL 2) · Vite 8 · Vitest 5. No UI framework, no physics engine.
Dev-only tooling: `tools/*.mjs` (headless Chrome via the DevTools protocol, Node built-ins only).

## Coordinates
1 unit = 1 m. +X east, +Z north, +Y up. Walkable world: [-3072, 3072]² (from `public/world/world.json`).
Compass heading 0° = north (+Z), 90° = east.

## Modules (`src/`)
| Folder | Responsibility |
|---|---|
| `core/` | config (sites, sun, palette), fixed-timestep `GameLoop` (60 Hz sim + rAF render), typed `EventBus`, `Input` (keyboard + pointer lock; UI focus gate), settings (localStorage, viewer prefs only) |
| `rendering/` | renderer/camera/lights/fog (`renderer.ts`, log depth buffer for 0.1 m – 30 km), Mars sky shader, dust motes, layer textures, `PartBuilder` (merges primitive parts per material), shared materials |
| `world/` | `WorldData` (r16 tiles → one Uint16 heightfield, splat decode, bilinear height/normal), `Terrain` LOD streaming, terrain splat shader, backdrop, `RockField`, colliders, model slots, PNG decoder |
| `player/` | `PlayerController` (camera rig independent of any body model), `SuitSystem`, `InteractionSystem` |
| `base/`, `vehicles/` | Placeholder outpost + reactor, drill rig state machine, rover placeholder |
| `missions/` | `MissionState`, objectives, records (story text, drafts flagged) |
| `ui/` | HUD, minimap/PDA map, menus, reader, PDA, DOM helper, CSS |

Simulation state (player, suit, mission, drill) never reads the DOM; the HUD is fed a plain `HudState` object each frame.

## Terrain streaming
- Data: 36 tiles × 513² uint16 heights (2 m), produced offline by `../Tools/python/prepare_world.py` from the CinderRain data.
  All tiles load at boot (≈19 MB, gzip-friendly) into one 3073² array — needed anyway for collision.
- Each 1024 m tile is either one coarse mesh (64 segs, 16 m) or 4×4 chunks of 256 m. Chunk resolution by Chebyshev
  chunk distance: ≤1 → 128 segs (2 m), ≤2 → 64, ≤4 → 32, else 16 (High). Tiles within 4 chunks are split.
- Vertices sit exactly on heightfield samples; normals from central differences; double-wound skirts hide LOD cracks.
- Builds are queued nearest-first and run under a 4 ms/frame budget; old meshes stay until replacements exist (no holes).
- **Web Workers:** not used. The heavy procedural work happens offline in Python; runtime meshing from the array is
  ~1–3 ms per chunk. Revisit if profiling on the target machine shows stalls.
- Backdrop: 257² grid to ±14.3 km; fragments inside the playable square are discarded.

## Terrain shading
Per-tile splat texture (RGBA = dark sand, bedrock, sediment, gravel; dust = remainder). Layers are the tileable textures
generated by `../Tools/python/make_textures.py`, sampled at two scales to hide tiling; bedrock is triplanar and forced on
steep slopes; a subtle height-based band adds strata. Splat PNGs are decoded by our own decoder because browser image
decoding premultiplies alpha and destroys weights where alpha = 0.

## Collision (Phase 02 decision)
Analytic, no physics engine: ground = bilinear heightfield; slope limit 40° (uphill velocity removed, slide when standing
on steeper); structures = vertical cylinders (`ColliderSet`); large rocks (> 0.45 m) = cylinders from the scatter.
Rationale: exact match to the rendered terrain at 2 m, zero dependencies, trivially cheap. A vehicle will need a
wheel-raycast model on the same heightfield (Phase 11).

## Rocks
6 procedurally fractured shapes, one `InstancedMesh` each (6 draw calls total). Scatter is deterministic per chunk,
only on finest-LOD chunks, density from gravel/bedrock weights + talus below steep ground + clustered noise, power-law sizes.

## Persistence
Settings in localStorage (viewer preferences); game progress in IndexedDB — see Saves below.

## Lifecycle
Resize handled; WebGL context loss shows a reload message; chunk geometries are disposed on unload.

## Cave (`src/cave/`)
- `caveDef.ts` — single source of truth: node/segment layout, chambers, a signed distance field (capsules + chambers,
  smooth union, warped-sinusoid wall noise, flat rubble floor), floor search, gradient, depth factor. No three.js import.
- `caveMesher.ts` (+ `caveMesher.worker.ts`) — surface nets on a 0.7 m grid; coarse pre-pass so only ~18% of samples are
  evaluated exactly; seals the domain; drops triangles above the hillside; normals from the SDF gradient; baked AO.
- `caveGlsl.ts` — GLSL generated from `caveDef.ts`: `cfCaveMouth` (terrain + terrain-shadow discard at the entrance) and
  `cfCaveDepth`; `patchCaveLighting` replaces three's `lights_fragment_begin` chunk so directional and hemisphere light are
  scaled by daylight visibility while point/spot lights (suit lamp, survey lamp) are not. The patch throws if three's
  chunk text changes, so an upgrade cannot silently break it.
- `ground.ts` — unified walkable surface: heightfield unless the mouth cuts it, cave floor inside the hill; cave walls and
  ceilings push the player capsule. Used by the controller and the camera clip guard.
- `cave.ts` — mesh/material, ice, beacons, Expedition 1 props, debris, talus; interactable anchors.

## Saves (`src/save/saveSystem.ts`)
IndexedDB `cinderfall2/saves/slot1`. Schema `SAVE_VERSION = 2`; `MIGRATIONS[n]` upgrades n → n+1; `validate()` checks ranges
and types; unreadable data → "corrupt" status shown on the menu, never a crash. Autosave every 30 s of play, on objective
and record changes, on pause, tab hide and page hide. A running drill is restored as idle (restart required).

## Audio (`src/audio/audio.ts`)
WebAudio graph created on the first user gesture. All sounds are synthesised: wind (low-passed noise), suit hum, breathing,
footsteps driven by distance walked, cave rumble/drips, convolution reverb from a generated impulse, HRTF-panned drill.
